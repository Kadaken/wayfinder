# Audit answers — Wayfinder

The 27 checks a program cannot decide. `scripts/audit-mechanical.sh` reads this
file. An id with no line at the version being released prints `OPEN` and blocks
the release.

One line per answer, exactly this shape:

    <id> @ <version> — <what was done and what it showed> (<date>)

Rules that make this worth keeping:

- The answer records what was DONE, not what is believed. "Looks fine" is not an
  answer. "Installed the tarball into a fresh user, first screen was the home
  view" is.
- A finding is a valid answer. An id whose answer is "this is broken, logged in
  REDO_REGISTER.md" is answered; whether it blocks the release is a separate
  decision.
- An answer is tied to a version. The next release re-answers every id. Carrying
  an answer forward unchanged is allowed only by writing it again at the new
  version, which forces someone to decide it is still true.
- Old versions stay in this file. The history is the point.

K9 @ 0.9.28 — Learned, not pushed: once a day the app curls one fixed URL on an allow-listed host and parses JSON. The manifest is validated before use (update.rs:120) — a version that is all zeroes, a URL off the download host, a sha256 that is not 64 hex characters, or a size below 100 KB or above 200 MB is refused. The download is size-checked against the manifest and then sha256-checked, and nothing is unpacked until the digest matches. Unpacking goes into a staging directory under the cache, and the archive must contain packaging/install.sh or it is rejected. The install itself is handed to a detached script that waits for this process to exit before overwriting the binary, because a running binary cannot be written to. Every failure returns a plain error and the app carries on; a failed check is not reported as a fault. What it is NOT: signed. The checksum is served by the same host as the tarball, so an attacker who controls kadaken.com controls both, and HTTPS plus the host allow-list is the whole of the trust. That is the honest limit of the current scheme and it ships in the unmeasured list (S10). (16 Nov 2026)

W2 @ 0.9.28 — unproven, and it is the one unmeasured security item this release ships with (see S10). Three D-Bus methods are exposed on org.freedesktop.impl.portal.FileChooser at the name org.freedesktop.impl.portal.desktop.wayfinder: OpenFile, SaveFile and SaveFiles (portal_service.rs:1218). No other method, property or signal is exported, which dbus_introspection_proves_bus_name_path_interface_and_signature checks against the live bus. What validates each argument: `handle` is accepted and ignored; app_id, parent_window and title are passed through as text and never used as a path; every option is decoded by a typed decoder that refuses rather than coerces — decode_current_name rejects a name holding '/' or NUL or equal to "." or ".." (portal_service.rs:823), decode_path_option rejects an interior NUL, a non-byte-string value and an empty path, decode_save_files_names rejects a list that is absent, empty, longer than MAX_SAVE_FILES (256), duplicated, or holding any name that is not one plain name, and decode_filters/decode_choices refuse malformed wire shapes. A Save with directory=true is refused outright, and `multiple` is never honored on a Save. On the way back out, three guards stand between the picker and the answer: exactly one path, a path that is absolute, and a target that is a real directory (Open/SaveFiles) or a writable file path whose parent directory exists (Save, save_target_is_writable). A picked path that is relative, missing, a directory where a file was asked for, or more than one path, is refused; a chooser that dies, writes nothing, writes a malformed result or misses its deadline fails closed, not as a cancel. The portal grants no folder the request did not ask for: the answer is built only from what the picker returned, and SaveFiles joins the one chosen folder with names that were already proved to be plain names, so no answer can name a path outside it. 26 dbus_* tests exercise all of this over a real bus connection with a real native child. What is NOT written, and why this reports unproven: a deliberate hostile run — a symlink that escapes the chosen folder, names holding newlines and control characters, absurd lengths (a 64 KB name, a path near PATH_MAX), and a path outside every granted folder presented from a hostile client rather than from the picker. (16 Nov 2026)

K2 @ 0.9.28 — Paths: every existence check and every removal goes through symlink_metadata, never metadata, so a symlink is seen as a link and never followed — entry_exists (native_core.rs:3829) and remove_any (native_core.rs:3837), which deletes a symlink-to-a-directory as a link and only calls remove_dir_all on a real directory. 41 symlink_metadata sites in native_core.rs against 18 metadata sites. fs::canonicalize is used in exactly 3 places, all in native_core.rs, and only to decide whether a source and its target are the same object before a move (plan_transfer_items), never to build a path that is then written. A broken symlink is an entry that is still listed and still moves (broken_symlink_destination_is_an_entry_that_is_never_lost_d24), and staged copies keep symlinks as symlinks (staged_copies_keep_modes_times_and_symlinks_d155). Traversal: the archive reader rejects a member whose name climbs out (rejects_parent_traversal_d188, rejects_traversal_name_inside_the_archive_d188) and rejects symlink members read through the real archive path (rejects_symlink_entries_through_the_real_archive_path_d188); the portal refuses a save name that escapes the chosen folder before the picker ever runs (dbus_savefiles_refuses_a_name_that_escapes_the_folder). Check-then-act: the deliberate defence is a full-content fingerprint recorded at the moment a history entry is made and re-checked before undo or redo touches anything, for renames, batch renames, pastes, moves and trash restores (D-187, UndoAction at native.rs:920). It hashes every byte of the file, or the whole tree, or the link target; a mismatch refuses the whole batch rather than restoring changed bytes. The transfer engine's own contract states the limit in writing: it is not crash-atomic and not safe against concurrent outside change, and an archive member swapped for one that keeps the same name, size and CRC is refused by fingerprint, not by CRC (extract_zip_member_rejects_replacement_archive_preserving_name_size_crc_d188). What this does not cover: the fingerprint is a 64-bit non-cryptographic hash (DefaultHasher), so it detects change, not a deliberately crafted collision — against an attacker who already has write access to the user's own files, which is not the boundary this guard exists for. And the portal's "the parent folder exists and the target is writable" guard is itself a check-then-act: a folder deleted in the moment between the guard and the calling app's write will fail in that app, not here. K4 @ 0.9.28 — Eleven places untrusted data enters, with the parser on each. (1) D-Bus options from any application on the session bus — typed decoders that refuse rather than coerce, detailed in W2; this is the only boundary where the data comes from another program rather than from the user. (2) The chooser child's result file, read by the portal parent — a strict reader where a malformed, empty, relative, multi-path or late answer fails closed (dbus_openfile_process_chooser_malformed_result_fails_closed and five siblings). (3) The update manifest over the network — serde_json into a fixed struct, then validate(): host allow-list, 64-hex digest, plausible size, non-zero version. (4) The downloaded tarball — size then sha256 checked before anything is unpacked, then GNU tar, and the unpacked tree must contain packaging/install.sh. (5) The app's own config file — serde_json into AppConfig, and a file that will not parse falls back to defaults. (6) File names, paths and link targets from the filesystem — drawn with set_text, which never interprets markup, and passed to child processes as argv entries, never through a shell (the one shell call passes the path as $1). (7) ZIP members — the archive reader rejects traversal names and symlink members and re-checks content by fingerprint, not by CRC (D-188). (8) .desktop files and mimeinfo.cache for Open With — read as text and parsed by hand; a malformed line is skipped, and the MIME type itself comes from xdg-mime, not from the file's own claim. (9) lsblk's JSON — parsed with serde_json into a typed shape, and an unreadable answer is an error, not a panic (native_core.rs:2448). (10) Media files — this is the widest boundary and the one not written by this project: images decode in-process through GdkPixbuf/GTK (7 call sites), sound through GStreamer, and video posters out of process through ffmpeg, which is the only one of the three that cannot take the app down with it.
